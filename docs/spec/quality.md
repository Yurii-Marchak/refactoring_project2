# Стандарти якості (Quality Standards)

Цей документ описує стандарти написання коду, правила типізації та метрики якості, яких дотримується команда при розробці платформи SubOptima.

## 1. Метрики SonarCloud (Quality Gate)

Для статичного аналізу коду інтегровано платформу SonarCloud. Пайплайн розгортання не буде пройдено (Quality Gate Fails), якщо код не відповідає суворим критеріям:

* **0 Bugs (Помилок):** У коді не повинно бути логічних помилок, які можуть призвести до збоїв у роботі (Runtime errors).
* **0 Vulnerabilities (Вразливостей):** Усі зовнішні ресурси (наприклад, підключення JS бібліотек) повинні мати SRI-хеші. Кукі мають передаватися з прапорцями `secure=True`, `httponly=True` та `samesite="lax"`.
* **Code Smells (Запахи коду):** Мінімізація застарілих конструкцій (наприклад, попередження про Deprecation від Pydantic чи Starlette мають бути своєчасно виправлені).
* **Coverage (Покриття):** Мінімально допустимий відсоток покриття коду тестами — 80%.

## 2. Типізація та Валідація (Type Hints & Pydantic)

Python у проєкті використовується як суворо типізована мова.
* **Type Hints:** Усі функції, методи та змінні повинні мати явні анотації типів (наприклад, `def get_user(user_id: UUID) -> User | None:`). Це допомагає IDE підказувати помилки ще на етапі написання коду.
* **Pydantic V2:** Будь-які дані, що надходять ззовні (через HTTP-запити), обов'язково проходять через моделі валідації Pydantic (схеми DTO).
* Замість застарілого `class Config:` у DTO завжди використовується сучасний синтаксис `model_config = ConfigDict(from_attributes=True)`.

## 3. Управління залежностями

Стабільність середовища розробки та продакшену забезпечується чітким контролем версій бібліотек.
* Будь-яка нова бібліотека встановлюється виключно у віртуальне середовище (`.venv`).
* Після встановлення нових пакетів файл залежностей обов'язково оновлюється командою:
  ```bash
  pip freeze > requirements.txt
