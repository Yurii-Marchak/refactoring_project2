# Фронтенд (Web Interface)

Цей документ описує архітектуру веб-інтерфейсу системи SubOptima. У термінах Гексагональної архітектури, веб-інтерфейс (Jinja2) діє як **Primary Adapter**, який використовує ті самі Use Cases, що й JSON API.

## 1. Базовий шаблон та UI-бібліотеки

Всі HTML-сторінки наслідують головний макет з файлу `base.html`. Цей підхід (DRY - Don't Repeat Yourself) дозволяє тримати загальні елементи, такі як навігаційна панель (Navbar) та підвал сайту (Footer), в одному місці.

**Використані технології:**
* **Jinja2:** Шаблонізатор для рендерингу HTML на стороні сервера (SSR). Використовує блоки `{% block content %}` для підстановки унікального контенту сторінок.
* **Bootstrap 5:** Підключений через CDN для швидкого створення адаптивного дизайну (сітка, картки, модальні вікна, кнопки).
* **Bootstrap Icons:** Бібліотека векторних іконок для візуального оформлення.
* **Chart.js:** Легка JS-бібліотека (підключена на сторінці аналітики з SRI-хешем для безпеки), яка малює круговий графік розподілу потенційної економії коштів.

## 2. Імітація авторизації (Cookies)

Оскільки проєкт є навчальним і не має повноцінної системи реєстрації/паролів, реалізовано механізм перемикання користувачів:
1. У навігаційній панелі (`base.html`) є випадаючий список згенерованих користувачів.
2. При виборі користувача форма відправляє POST-запит на ендпоінт `/web/set-user`.
3. Сервер встановлює ідентифікатор користувача в Cookie (`user_id`) з прапорцями безпеки `httponly=True`, `secure=True`, `samesite="lax"`.
4. Всі інші веб-маршрути читають це Cookie через `Depends` і віддають лише ті підписки та аналітику, що належать обраному користувачу.

## 3. Взаємодія JS з бекендом (AJAX)

Щоб інтерфейс був швидким та інтерактивним, оформлення підписок та відправка фідбеку відбуваються без перезавантаження сторінки.

**Логіка роботи модальних вікон:**
1. Користувач натискає "Підписатися" або "Залишити відгук", що відкриває модальне вікно Bootstrap.
2. Користувач заповнює HTML-форму (вибір тарифу або переміщення повзунків оцінки `range`).
3. При натисканні кнопки "Підтвердити", викликається нативна JavaScript-функція (наприклад, `submitSubscription`).
4. JS-код збирає дані з форми, формує JSON-об'єкт та відправляє асинхронний запит через **`fetch API`** на відповідні REST-ендпоінти (`/subscriptions` або `/feedback`).
5. У разі успіху (статус 2xx), модальне вікно закривається через JS API Bootstrap, і сторінка оновлюється або перенаправляє користувача. У разі помилки виводиться `alert` із текстом помилки від бекенду.
