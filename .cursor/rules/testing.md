# Стратегія тестування (Testing Strategy)

- [cite_start]**Цільові метрики:** Мінімум 200 модульних та інтеграційних тестів, загальне покриття коду (Code Coverage) >= 70%[cite: 5, 6].
- [cite_start]**Фреймворк:** `pytest` із плагіном `pytest-cov` для аналізу покриття гілок логіки[cite: 6, 31].
- [cite_start]**Ізоляція:** Для ізоляції шарів бізнес-логіки використовуйте Mock-об'єкти (`unittest.mock` або `mockito`) замість реальних викликів інфраструктури[cite: 34].
- [cite_start]**Генерація даних:** Для тестів аналітики за 12 місяців використовуйте автоматично згенеровані тестові дані (fixtures), імітуючи різні патерни поведінки користувачів (активні користувачі, користувачі з "мертвими" підписками)[cite: 70, 73, 79].
