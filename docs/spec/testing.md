# Тестування (Testing Strategy)

Цей документ описує стратегію забезпечення якості коду платформи SubOptima. Проєкт має високий рівень покриття коду (Coverage > 80%) завдяки використанню фреймворку `pytest`.

## 1. Структура тестів

Тестовий набір організований відповідно до шарів Гексагональної архітектури та розміщений у директорії `tests/`. Це дозволяє ізольовано перевіряти кожен компонент системи.

* **`tests/models/`**: Перевірка доменних сутностей. Тестується правильність створення об'єктів та базова валідація даних (наприклад, неможливість створити тариф із від'ємною ціною).
* **`tests/use_cases/`**: Ізольоване тестування бізнес-логіки. Тут перевіряється математична модель (Fuzzy Logic), правильність розрахунку Utility Score та генерація рекомендацій.
* **`tests/storage/`**: Інтеграційні тести для перевірки роботи адаптерів бази даних (як `in_memory`, так і `mongodb`).
* **`tests/api/`**: Тестування Primary Adapters (REST маршрутів та Web UI). Перевіряються HTTP-статуси, обробка невалідних JSON-запитів та поведінка Jinja2-шаблонів (наприклад, при відсутності кукі).

## 2. Тестування бази даних (mongomock)

Для тестування адаптерів MongoDB без необхідності піднімати реальний сервер бази даних використовується бібліотека **`mongomock`**.
* Вона імітує поведінку `pymongo` в оперативній пам'яті.
* Це дозволяє запускати тести миттєво в середовищі CI/CD (GitHub Actions).
* За допомогою `mongomock` генеруються Edge Cases: спроби оновлення неіснуючих документів, вибірка з порожніх колекцій та перевірка поведінки системи при некоректних типах даних у БД.

## 3. Перевірка Edge Cases (Параметризація)

Для перевірки граничних випадків (Edge Cases) та уникнення дублювання тестового коду активно використовується декоратор **`@pytest.mark.parametrize`**.

**Переваги підходу:**
* Одна тестова функція може бути запущена з десятками різних комбінацій вхідних даних.
* Це дозволяє ретельно перевірити обмеження (наприклад, якщо оцінка `frequency_1_to_7` дорівнює 0, 8, -1 або є рядком).
* Такий підхід гарантує, що система не "впаде" при отриманні нетипових значень від клієнта і коректно відпрацює викидання `ValidationError`.
